Backend of the grooming service of a pet shop, built with Spring Boot, Spring Data JPA and PostgreSQL. A pet owner books a grooming session done by a groomer; each groomer works in one grooming bay and can be trained for several pet types. A session moves from BOOKED to IN_PROGRESS and ends FINISHED or CANCELLED. Once it is finished, the groomer records the care products sold to the owner.

## Technologies

- Java 26
- Spring Boot 4.1.1 (Spring Web, Spring Data JPA)
- PostgreSQL
- Maven (Maven Wrapper included)

## Entities

PetType, GroomingBay, Groomer, PetOwner, GroomingSession (with the enum SessionStatus) and ProductSale. Every entity has a UUID id generated by JPA.

## How to run the API

1. Install a JDK, PostgreSQL and Git.
2. Clone the repository:
   ```
   git clone https://github.com/David25781/pet-shop-management-system-backend.git
   cd pet-shop-management-system-backend
   ```
3. Create the database in PostgreSQL:
   ```sql
   CREATE DATABASE pet_shop_db;
   ```
4. Open `src/main/resources/application.properties` and set your PostgreSQL user and password:
   ```
   spring.datasource.url=jdbc:postgresql://localhost:5432/pet_shop_db
   spring.datasource.username=postgres
   spring.datasource.password=YOUR_PASSWORD
   ```
   The tables are created automatically (`spring.jpa.hibernate.ddl-auto=update`) and the SQL is printed in the console (`spring.jpa.show-sql=true`).
5. Start the API:
   - Windows PowerShell: `.\mvnw.cmd spring-boot:run`
   - Linux or macOS: `./mvnw spring-boot:run`
6. The API listens on the port set by `server.port` in `application.properties`.

## Seed data

The seed data of the paper (Step 0) is entered through the API itself, with the save endpoints, in this order: pet types, grooming bays, pet owners, groomers, grooming sessions. The save endpoints receive the id of the related objects, for example `"groomer": {"id": "..."}`.

## Postman

The file `pet-shop-management-system-midterm.postman_collection.json` at the root of the repository has one request per requirement, named by its ID (A1, A2, B1, B2, B3, C1 to C4, D1 to D4, E1 to E3, F1, F2, Bonus-Dashboard and Bonus-Page). The collection variable `baseUrl` holds the address of the API. The ids inside the requests belong to the author's database; after a new seed, replace them with the ids returned by the `/all` endpoints.
